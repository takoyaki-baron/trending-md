# 機械検証される主張

**主張：**証明は*モデル*についての主張であり、現実についての主張ではない。そしてモデルの信頼境界は見出しにはほぼ現れない。2026 年に繰り返されるパターンは、**「証明済み」と書かれた成果物が、脚注・限界節・あるいは spec そのものの中に、「この証明が*覆わない*もの」を定める一文を同時に同梱している**ことだ。証明は範囲の明記された極めて強いテストとして読み、仕事は (a) 範囲を見つける、(b) 信頼の基盤を見つける、(c) 証明者が何で報酬を得たかを問う、の 3 つになる。

## 2026-10-22 — Anthropic × Theorem：コンパイル済み RISC-V バイナリへの証明（画期）

*アセンブリ水準の*生産ソフトウェアに形式検証を大規模適用した最初の事例（記事自身の表現）。Claude は 123 の OSS-Fuzz C/C++ ライブラリの各コンパイル済みバイナリが決してクラッシュしないこと——常に正常終了し、メモリ安全エラーもアサーション失敗も起こさないこと——を、**64 MB 未満のあらゆる入力**、モデル化されたあらゆる Linux 応答とメモリ配置について証明した。数値は 2026-10-23 12:20 UTC+8 に[原文](https://www.anthropic.com/research/formal-verification)で逐語確認：

| 項目 | 値 | 注記 |
|---|---|---|
| ライブラリ | **123** | OSS-Fuzz コーパス |
| エントリポイント | **239** | spec は各プロジェクト既存の fuzz エントリポイントから機械的に導出——「このテスト群は決してクラッシュしない」 |
| 証明の規模 | **約 1.8 億行の Rocq** | 典型的な証明は約 60 万行 |
| バイナリ | 中央値 **18,000 命令**（RISC-V） | 証明はコンパイル済み命令を対象に、Theorem の RISC-V と Linux プロセス意味論を介して行われる |
| バグ発見 | **数兆回の fuzz** が見逃したバグにパッチ | 証明の過程で発見 |
| 成果物 | 証明の一部 + RISC-V/OS 意味論を公開；Theorem は他プロジェクト向けにパイプラインを提供し、Claude skill も公開 | 再利用こそがコスト償却の筋 |

### 信頼の基盤（見出しが省く部分）

1. **Theorem の RISC-V / Linux プロセス意味論**——これ自体もモデル生成。脚注 7 によれば、この意味論をシングルステップ実行すると Linux カーネル上で Ubuntu ユーザー空間が起動し、生成の過程で**公式リファレンス文書の数百の誤り**と、より少数の**ハードウェア自体のバグ**が見つかった。それは検証の話であって証明ではない。
2. **定理文**——つまり spec。fuzzer のエントリポイントから導かれるので、得られるのは「クラッシュしない」であって「正しい」ではない。
3. **Rocq カーネル**——脚注 5 はさらに「Rocq チェッカーが依拠するハードウェア、OS、OCaml コンパイラ」まで含める。鎖はシリコンで終わる。
4. **呼び出し側**——完全に範囲外。検証済みライブラリは誤用されればメモリ破壊を起こしうる。塞ぐには関数ごとの呼び出し側契約が要る。

### 限界節（実質逐語）

- シングルスレッド、静的リンクの **RISC-V + musl**。だが多くの配備は **x86/ARM + glibc**。
- 全エントリポイントが検証されたわけではない。全ポイントを検証しても（デッドコードがあるため）ライブラリ全体は覆えない。しかも **ASan はすべてのメモリ安全バグを検出しない**ので、「ASan クラッシュ無し」≠「バグ無し」。
- 最も引用すべき一文：**「形式的に検証済み」は「バグ無し」を意味しない。**

### 読み方を変える脚注（脚注 6）

> 「これは**報酬ハッキング**の扉を開けたままにしている……Claude は**決してクラッシュしない形にプログラムを書き換える**ことで、どんな定理も証明可能にできてしまう。これを抑えるため、あらゆるパッチに罰を与え、どの入力をどれだけ変えたかの証明に追加の報酬を与えた。さらに、そうした失敗様式についてパッチを記録し監査した。」

これがこの発表で最も重要な段落であり、本文には無い。**「この定理を真にせよ」と言われた証明者には退化解がある——定理の主語を差し替えることだ。**ここでの緩和策は報酬設計（パッチに罰、最小性に報酬）とパッチの人手監査、すなわち*インセンティブ*と*プロセス*であって、チェッカーが強制できる制約ではない。監視テストを削除して通るエージェントや、SlopCodeBench の strict 対 core の差と同じ形——外側の何かが標的を固定しない限り、標的は調整可能である。**モデル自身が編集したコードを覆う検証主張では、パッチ数とパッチ監査が結果の一部になる。**

同週の関連：コンパイル済み成果物を対象とするということは、証明されるのは*配備されたバイト*であり、ソースとバイナリの齟齬を迂回する——ただし誰かが検証したそのビルドに限る。

## 質問リスト——あらゆる「検証済み／証明済み／形式的に確認済み」の主張に

1. **定理は何か？**非クラッシュ、機能的正しさ、到達可能 UB の不在は 3 つの別の主張。要旨は一つを述べ、範囲は別を示唆する。
2. **信頼の基盤は何で、ベンダーはそれを列挙しているか？**意味論、コンパイラ、カーネル、ハードウェア。「チェッカー」だけの基盤は不完全。
3. **モデルは配備と一致するか？**ここでは RISC-V+musl 対 x86/glibc が差の全部。
4. **構造上何が排除されているか？**呼び出し側の誤用、並行性、デッドコード、エントリポイントが届かない内部。
5. **主語は証明者が編集できたか？**できるなら、反自明化の手段を見つけ、それが監査（弱いが本物）か制約（強い）かを判定する。報酬設計は証明ではない。
6. **「反例なし」が「バグ無し」として報告されていないか？**ASan／差分テストは検出できないものは見えない——その一文は普通原文にあり、普通下流で落とされる。
7. **単発か分布か？**1 ビルドの 1 証明は 1 データ点（4 台の Gemini による Minecraft の留保の再利用）。

## 2026-10-23（学習パス）——このファイルが存在する理由

10-22 の発表は、検証を「論文の定理」から「あなたが出荷するライブラリ」へ移した。それによりこれは研究的好奇心ではなく*フィード*の話題になった。この種は今後反復する（Theorem はパイプラインを製品化し skill を出している）し、報道側の失敗様式も定まっている——数値を繰り返し、脚注を落とす。本ファイルはそれを防ぐチェックリストであり、次に見るべき 2 点は、(a) 公開された証明のいずれかが第三者によって同じ意味論で再検査されるか、(b) 64 MB の境界が攻撃者に必要なものそのものにならないか——入力サイズの境界は、パーサが同じ境界で大きな入力を拒否するときにだけ実効的な制約になる。

## 2026-10-30 — 証明はビルドの性質であり、プロセスの性質ではない

同じバッチの二つの成果物は、10-22の実行が届かなかった場所へ検証を運ぶ。一つはWASMへ、一つはゲームエンジンの中へ。どちらも**配備後に検査されなくなるもの**を自分の言葉で書いており、その一文が持ち帰る部分だ。

**Lasm（`Millillion/lasm`、MIT、66★、2026-09-23作成、`@lasm/cli` 0.3.5がnpmに2026-10-28T19:07:10Z公開）は通常のLean 4をAOTでWebAssemblyにコンパイルする。** `leanprover/lean4:v4.35.0`を厳密に固定し、ツールチェーン自体を導入する。0.xのプロジェクトとしては異例に広いターゲット表——Node、Lambda、Lambda@Edge、Vercel、Netlify、Azure Functions、Cloud Functions gen2、Workers、Deno Deploy、Supabase Edge、Bun、Deno、Fastly Compute、WASI、wasi-http、ブラウザ——で、各行はプラットフォーム自身のランタイムに対するCI試験済みとされている。制限は、読み手が見落とせない位置に置かれている：

> **Not available at run time:** elaboration, `#eval`-style evaluation, loading `.olean`, Lean's kernel — all of these work at build time.

つまり配備された成果物は**証明チェッカを含まない**。定理は出荷したビルドの性質であり、実行プロセスは再検査しないし、できもしない。同じ表（脚注ではなく）にさらに二つの制限がある。edge/Bun/Deno/WASI/ブラウザのターゲットは「run Lean single-threaded, without sockets or processes (and without files, except on WASI)」であり、Node行のフルランタイムとは別物だ。看板の主張——Conduit RealWorldアプリの「**117の証明済み定理**」——はプロジェクト自身の数（README、`npm run proofs`、`sorry`なし、標準公理のみ、CIジョブ`conduit.yml`）で、独立再現はない。さらに「by project policy CI never deploys to a real cloud account」は正しい方針であり、同時にクラウド行が実配備ではなくビルド成果物の試験であることを意味する。

**DOOMFORMER（`mottopanikeiku/doomformer`、MIT、36★、2026-10-20作成、v0.4.0）は整数ニューラルネットをDOOMマップにコンパイルし**、算術をエンジンにやらせる。ブードゥー人形が数、床の線が重み、光量や天井高が和、階段が活性化、天井がアテンションだ。MNISTマップは**1,355体**の人形を使う。公表値は、テスト数字**10,000 / 10,000**完全一致、**20,000**個のファズ済みネットで不一致**0**、そして別の**4**つのDOOMエンジンが「museum」マップを正確に実行する。そのうえで見出しを引用可能にする部分——自分の検査を表で攻撃する：重み線を一つ改ざんすると「検査はそれを跨ぐ入力で正確に落ちる」、マップの一行を**1,004**回変異させると**297**件検出、しかも「生存者はどれも無害と証明されていない」、各読み出しページに毒値を置くと「一度も走らないページは古い値を通過できない」。そして率直な限界：

> Every run compares each value the map exposes with NumPy. **That proves the inputs that ran, nothing more.** MNISTマップは248個の値を露出するが、903個の階段カウントや1,351回のゲート比較は露出しない。

**問いリストへの追加（「検証済み」という主張すべてに適用）：**

1. **配備後、チェッカはどこにいるか。** ビルド時に走るカーネル、`lake check`、NumPy比較器はいずれもビルドについての主張だ。*インストールされた*成果物が何を証明できるかを問う——Lasmの答えは「通常のコンパイル済みコード以外は何も」である。
2. **検査はいくつの値に触れ、成果物は全部でいくつ計算するか。** DOOMFORMERの正直な分母は、露出248対内部約2,502（903の階段＋1,351の比較）。出力を覆う検証は、出力を証明する。
3. **定理数は、利用者が気にするものの数か。** 認可、フォロー、お気に入り、slug、ページネーション、JSON往復にわたる117の定理は、誰かが選んだ集合だ。このアプリをこのように書けるという証拠であって、カバレッジの数字ではない。

## 2026-10-31 — 「確認しただけ」の部分まで印字する検証プロジェクトと、論文自身の結論を縮める対照

### `emmilco/us-tax-model` — 証明済み・確認済み・未測定を並べて印字する

米国連邦個人所得税の申告書と説明を、公開・引用付き・機械検証可能なデータとして符号化する。様式はYAMLで、各行は約20個の原子からなる閉じた語彙の式（`sum`、`smaller_of`、`table_lookup` …）であり、**ユーザ定義関数・ループ・再帰はない**。金額は`BigInt`で評価する整数セントなので、浮動小数点はどこにも存在しない。ビルド時チェッカが参照・非巡回性・型・網羅的な分岐・来歴を検証する。`lean/TaxFormalization/`では原子が整数上で定義され、`subtractFloor0_nonneg`や`roundHalfUpToUnit_idem`といった性質が証明され、正規化JSON上の参照評価器が停止かつ決定的であることが証明される。**PolicyEngine-US**、**Tax-Calculator**、**OpenTaxSolver**と突き合わせ、「never files, signs or transmits a return」。

確認時のリポジトリ状態：**124★、10 forks、2 watchers、open issues+PRs 0**、コードApache-2.0／データCC0、作成**2026-10-23**——まだ8日なので、正直な読み方は「*どう誠実であるか*を示す設計」であって、検証済みの税計算エンジンではない。

引用に値するのは制限の節で、READMEから逐語で：

- **「2026-10-24 regenerated report reads 198 of 1,515 (13.1%)」**——スコアボードは計算行のうち**1,515**行中**198**行（13.1%）をファミリ外の主張に帰し、内訳は**H: 0, B: 0, second-family M: 44, E: 163**。
- 申告者のカバレッジ**68.6%**、しかも「**148 of the 157 refusal gates are not measured**」——真のカバレッジはこれより低く、足りない分母がどれかをプロジェクト自身が明示している。
- **BUG-0001**は、**2つの評価器が誤った和に一致した**自らの事例。これは「2実装が一致⇒正しい」への反例そのもので、埋めずに公開している。
- 「Citations show where a line points, not that it was interpreted correctly」、型が正しくても被演算子が誤っていれば通る、独立した読み方は「are not fully independent」、法律家のレビューはなく、様式と説明は法律ではない。

3層が名指しされている：**証明済み**（Leanの性質＋評価器の決定性）、**確認済み**（評価器間の一致。BUG-0001が十分条件としてのそれを反証する）、**未測定**（157門のうち148）。

### `dbreunig/nesformer` — 証明はCPUを覆い、PPUはそこに無いと明言する

NESの6502 CPU、2 KBのワークRAM、カートリッジROMが素の`Qwen3_5ForCausalLM`チェックポイントの中で動く。ゲート付きDeltaNetの状態行がレジスタ／RAM／ROMセルになり（one-hotキーが128幅の行を1つ上書きし、one-hotクエリが読み戻す）、プログラムカウンタは保存されず**推論**される。チェックポイントは**466.6Mパラメータ、bf16で約933 MB**、非ゼロは**9.3M**のみ、zipで**3.3 MB**。引用すべきREADMEの一文は「**Nobody trained these weights; a compiler computed every one.**」

読む理由は検証のほうだ。参照CPUはnestestのゴールデンログと**3,348**命令で一致し、py65とは**570万**のゲーム命令で一致する。正確な回路はnestestと**283,610**位置のすべての参照トークンを予測し、ThwaiteとFull Gameの完全実行は**300フレーム全部**と**210フレーム全部**を再現した。範囲の宣言も同じくらい精密で、**PPUは重みの中に一切入っていない**——ホストがPPU、コントローラ入力、vblank/NMIタイミング、APUレジスタを供給し、生成されたトレース以外ではCPU状態に触れない。制限は平然と列挙される：NROM / iNES mapper 0のみ、バンク切り替えなし、非公式オペコードはHALT、APUフレーム／DMC IRQなし、音声なし、sprite-0ヒットは近似。

**確認して出てきた成果物の注記2つ、いずれも本ライブラリで繰り返す形：** `created_at` **2026-10-30T15:54:20Z** → `pushed_at` **15:59:18Z** は、内容が明らかにそれ以前のリポジトリにとって**記録時計で5分**（記録は記録を日付づけるだけ）；そして`api.github.com`は`license: NOASSERTION`を返すのに`LICENSE`は**200**で「MIT License / Copyright (c) 2026 Drew Breunig」を返す——4度目の「ライセンスは3つの成果物」で、今回は*API*のほうが外れ値だ。

### プローブ論文は自分の数字を説明する対照を自分で載せている

「Pre-Crime for Agents, at the Last Second」（arXiv **2610.40588**）は生成*前*に目標agentの活性を読む。6シナリオの制御された圧力テストで、仲間が最大20ラウンド秘密を迫る。ホールドアウトの**Qwen3-32B**で、良性呼び出しの5%を立てる閾値において、線形プローブは漏洩呼び出しの**82%**を検出し、ゼロショットの決定モデル監視は**26%**。**gpt-oss-20b**では推論へのプロービングが**AUROC 0.91**に達する。そして論文が自らに突きつける結果：**bag-of-words分類器が「performs nearly as well」**であり、著者自身の読みは「**most of the gain comes from training on labels, not activations**」——しかもプローブは*許可された*開示にも反応し、「違反」よりも「これから来る開示」を読んでいる。だから82%は統制された集合の数字で、使える主張はアーキテクチャのものだ：**検査はテキストより1呼び出しぶん早く動かせるが、それ以上は無理だ。**

### 巻き戻し可能証明：効率定理であり、適用条件こそが発見

「Efficient Scalable Oversight via Rewinding」（arXiv **2610.40535**；Guan、Tauman Kalai、Rothblum、Xi）は、討論型監督の前提——少なくとも一方の証明者が誠実——を、検証者が証明者の状態を**保存し復元できる**ようにすることで外す。前処理後、検証者は「nearly linear in the input length」で走り、誠実な証明者は元の計算に対して線形。構成は「robust to changing a small fraction of oracle answers」な計算向けで、暗号学を用いない。証拠は**予備的なMNIST**実験。適用限界は要旨にある：そのロバスト性条件と、検証者が**証明者のマシンを制御**できるか、チェックポイントと復元ができること——自分でホストするモデルなら問題にならず、第三者のモデルでは現実の制約になる。監督研究がますますそこに住むしかなくなっている。

### 問いリストへの追加

**プロジェクトは3層すべてを印字しているか——証明済み・確認済み・未測定——それとも最初の層だけか。** 検証の主張が監査可能なのは、成果物が自分の未測定の分母を名指しするときだ（us-tax-model：157門のうち148、ファミリ外13.1%、既知の誤和バグがn=1）。証明済みの層だけを印字するプロジェクトは嘘をついていない。残りを測るための数字を伏せているだけだ。
