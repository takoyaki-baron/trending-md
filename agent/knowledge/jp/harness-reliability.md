# Harness信頼性——耐障害性とトークン効率はどちらもモデルとツールの継ぎ目に住む

48時間以内に公開された3本の論文（arXiv、2026-10-23）が、同じ物理的な場所を3方向から測っている。エージェントがアクションをツールに渡し、結果を読み戻すあの継ぎ目だ。1本はそこへ故障を注入し、1本はアクションが継ぎ目を越える前に検証し、1本はすでに解決した決定を継ぎ目越しに再利用する。3本とも同じ変数に到達する。数字を動かすのは**harness**であって重みではなく、そしてどの論文も自分の測定の限界を紙面に印刷している。

隣接ファイル：[[agent-stack]]（harnessという製品カテゴリ）、[[token-economics]]（コスト境界）、[[fact-check]]（自己申告の表の読み方）、[[frontier-models]]（ベンチマーク表におけるharnessプレミアム）。

**主張：** 信頼性とトークン効率はどちらも**モデル–ツール境界**の性質であり、その境界はチームが今週変更できるコードである。能力ベンチマークは脆さを見えず、モデルの規模はそれを買えず、報告された最大の節約は*決定を再導出しないこと*から来るのであって、より良い推論からではない。

## 3つの計器

| 論文 | 継ぎ目で何をするか | 見出しの数字 | 自ら述べる限界 |
|---|---|---|---|
| **MCP-Injector**（arXiv 2610.32555） | MCPツール呼び出し経路に故障注入ミドルウェアを差し込む。永久／一時／間欠、シード可能なスケジュール | 永久故障が重いプロファイルでタスク完了スコアが **60%** 低下（8.08 → 3.23 / 10） | プロファイルは**issueスレッドから採掘**した代理指標で、永久寄りに重み付けされている。重み付けを変えれば60%は動く |
| **StateMirror**（arXiv 2610.32648） | 実行*前*にアクションを横取りし、AST＋コマンド解析で状態述語を抽出し、生きたリポジトリに対して決定的に検証する | 2,508アクションで **precision 0.940 / F1 0.817**、検出遅延 **17.73 s → 1.50 ms**、トークン消費ゼロ | 捕まえるのはエージェントの環境モデルと環境の不一致だけ。*妥当だが誤った*呼び出しは見えない |
| **HarnessMM**（arXiv 2610.32813） | 解決済みの決定を実行可能決定グラフとして保存し、推論を再呼び出しせずレシートから再生する | HumanEval：成功率を **90.82%** に保持しつつトークン/タスク **66.72k → 47.02k（29.54%）**；DeepSeek Harness：成功率 **71.43% → 85.71%**、トークン **96.28k → 11.62k（87.93%）** | 関数レベルのベンチマークのみ。DeepSeek行の14ポイント*上昇*は説明されておらず、ベースラインの調整不足として扱うべき |

## MCP-Injector：規模は耐障害性を買わない

- **故障モデルは生態系から採掘**されていて、発明されていない。**1,774のオープンソースMCPリポジトリにわたる57,240件のissueとPRスレッド**を（故障モード × 永続性）で分箱した。
- **1,350セルのグリッド**が、2つのバックボーン規模（20B、120B）、3つのスタック（自作のマルチラウンド plan-and-execute、OpenAI Agents SDK、LangChain）、3つの故障条件を交差する。
- **慎重なのは負の結果のほうだ。** 120Bは故障下で「故障なしスコアのより大きな割合を保持しない」（レジリエンス比モデル、**p = 0.96**）、故障時の完了率は「差があるとすれば低い」——**91.1% vs 95.6%**、差4.4ポイント、95% CI **[-0.2, 9.3]**。ゼロをまたぐ信頼区間は*発見ではない*と書かれている。この一文はどんな表にも写す価値がある。
- **実務を変える一文：**「エージェントスタックは故障の吸収の仕方が異なり、これはフレームワーク層のエラー処理がモデル規模より重要であることを示唆する」。したがって信頼性はharnessの予算項目であり、モデル選定の判断基準ではない。
- **両バックボーンとも `gpt-oss`**——2モデル系列であり、分野の調査ではない。

## StateMirror：「幻覚」のうち判定可能な半分こそ大きい

- **まずベースライン費用を測っている。** 4,398本の軌跡から、幻覚的なツール利用は回復に中央値で**3ステップの追加対話と22.4Kトークン**を要する。既存フレームワークは実行*後*にエラーをフィードバックして捕まえるからだ。
- **手法は、モデルを必要としない部分をモデル化しないことへの拒否**だ。パス・パッケージ・シンボルに関する述語は、生きたリポジトリに対して判定可能である。これで最強のLLMジャッジより **F1で35.3%** 上回り、遅延は4桁改善し、**トークンはゼロ**——だからこそサンプリングではなく*すべての*アクションで走らせられる。ガードレールは防ぐ失敗より安くなければならない。高くつく「ガードレール」は指標である。
- **79タスクでの実地緩和：** 実行時間 **−15.8%**、トークン消費 **−11.8%**、タスク解決率は維持。
- **論文自身が書く境界：**「妥当だが誤り」（誤った理由で通るテスト）は検出対象のクラスの外にあり、0.817というF1はそれが設計されたクラス上で測られたものだ。

## HarnessMM：節約の大半は「以前に解決したこと」から来る

- **機構：** 実行可能決定グラフが正確なアクション、リテラル引数、因果依存、*公開ガード*を保存する。コントローラが観測したレシートからそれらを起動し、ネイティブインターフェース経由で実行し、登録された遅いコールバックの除去を記録する。アクターの重みは**凍結**されたまま。新しい決定、未対応の証拠、セレクタの棄権はモデルへフォールバックする。
- **移植できるアブレーションは見出しのものではない。** MBPPで、決定を保持することは単発利用のグラフより **26.91%** 安く、保持コールバックより **19.52%** 安い——つまり利益の大半は*その決定を一度解決したこと*から来ており、周囲のグラフ機構からではない。
- **疑うべき行：** 同じ行でトークンを87.93%削りながら成功率を14ポイント上げるのは、通常ベースラインの調整不足を意味し、論文はその上昇を帰属していない。
- **報告されていない実験：** 公開ガードで*生きた*環境に対して検証される決定グラフは、呼び出しの間に状態が変わる実リポジトリで最も壊れやすい構造そのものだ。HumanEvalとMBPPは関数レベルである。

## フィード項目に持ち込むべきこと

1. **継ぎ目を名指しする。**「エージェントが賢くなった」は測定ではない。「スタックが故障を吸収した」「述語が実行前に検証された」「決定が再利用された」はすべて測定であり、すべてコードである。
2. **節約と同時に届く改善を疑う。** 結果保持＋コスト減はキャッシュの主張。結果上昇＋コスト減は、著者がそう言うまではベースラインの主張だ。
3. **故障モデルを引用する。** ストレスプロファイルは選択であり——issueスレッドから採掘し永久寄りに重み付けしたもの——見出しの割合はその選択の性質である。
4. **判定可能なものと判断を要するものを分ける。** 幻覚の安い半分は環境に対して判定可能で、高い半分はそうではない。混同すると安い半分が不可能に見える。
5. **ガードレールにとって遅延は正確性の性質である。** 17.73 s → 1.50 ms が、サンプリング検査を常時検査へ変えた。

## スコアは「ペア」のものであり、「産出できなかった」は別の失敗である (2026-10-26 20:38)

arXiv 2610.32483（*When Agents Fail: Model or Harness — Who's to Blame?*）は、このファイルの前提に必要だった
主張を与える：agentic ベンチマークの数値はモデルではなく**モデル–ハーネスのペア**の性質であり、
それを見る方法は**有効完了**と**正しさ**を分けて測ることだ。

- **5つの指標：** Valid Completion Rate（VCR——正しさに関係なく、agent が正常に終了し*評価可能な*結果を
  出せたか）、Model-Harness Fit、Cross-Model Fit、Interaction Residuals（構成要素レベルの要約に隠れる
  ペア固有の強弱）、Token Load（失敗した試行を含む）。
- **規模：** 4つのハーネス——**OpenCode、Codex CLI、Pi CLI、DeepAgents**——×4つのコアモデル、加えて固定の
  ネイティブ・モデル–ハーネス系2つ、6つのベンチマーク（文脈管理、ツール使用、長文脈計画、マルチモーダル相互作用、
  成果物の受け渡し）にわたり：**111 設定、52,168 軌跡**。
- **所見：** **OpenCode がクロスモデル性能で1位**；**DeepSeek V4 Flash Preview** が共有4ベンチパネルで
  ハーネス横断の最高平均 VCR；著者自身の要約が引用すべき文である——"harness rankings vary across models and
  benchmarks; task performance and valid completion can favor different pairings, and similar task
  scores can accompany distinct execution profiles."
- **なぜ VCR が荷重を支えるのか：** 正解率だけでは、評価可能な成果物を一度も出さなかった agent と、
  誤った成果物を出した agent が同じ点になる。これは別々の欠陥で直し方も違う（ハーネスの配管 vs モデルの判断）が、
  標準的なベンチ表はそれを潰してしまう。

**同伴する留保：** 査読中のプレプリントであり、111 設定は著者自身が構築したもの。ランキングが不安定であることの
実証として読み、引用するリーダーボードとしては読まない。

**同じ問いのスキル側**（arXiv 2610.32322、*Beyond Gain*）：スキルの有無による**利得**で退役を決める規則は、
利得がゼロ付近になる2つの場合を区別できない——スキルが内化されている場合と、モデルもスキルも能力を提供しない
場合（**uncovered**）である。4モデルでの実測：**SkillsBench の31件の退役のうち28件は、どの実行も完全には
通らなかったプローブに依拠している**；利得規則のタスク間一致は **Cohen's κ 0.23** で、無補助スコア判定の
**0.42** に対し、判定は**モデルごとに異なる**ため hub は "must read them per model"。
1,251 スキルとタスク・項目別スコア（4モデル）が `EverMind-AI/SkillCorpus` として公開されている。
