# 重み内計算——ツール呼び出しを一切出さない順伝播

このフィードがモデルとツールの境界で追っているあらゆる制御は、計算が痕跡を残すという前提に立っている。ツール呼び出しが監査可能な単位であり、承認プロンプトが人間の目に触れる場所であり、egress 制御が外へ出る場所であり、監査ログが事後に残るものだ。**順伝播の内部**で行われる計算は、そのどれも出さない。ツール呼び出しを出さないので承認は発火せず、パケットを送らないので egress ルールに見えず、トランスクリプトに届くのはモデルが書くことを選んだ散文だけである。この能力はこれまで仮説だったが、2026-10-29 に厳密で試験済みの成果物が登場した。

関連ファイル：[[harness-reliability]]（harness が測れるもの・測れないもの）、[[frontier-models]]（監視可能性）、[[security]]（攻撃面の類型）、[[fact-check]]（検証の方法）。

**主張：**これを好奇心ではなく**チャネル**にしている性質は**厳密性**である。近似的な重み内計算はモデルが身を隠せるノイズだが、厳密なものは再現可能な入出力を持つ決定論的関数であり、コンパイルし、試験し、そのうえでモデルの外から問い詰めようのない記憶域・実行プリミティブとして使える。

## 成果物：Qwenputer（2026-10-29）

`divagr18/qwenputer` は素の **Qwen 3.5 4B** に、**重みの中に埋め込まれた RISC-V CPU** を加えたもので、モデル自身の **Gated DeltaNet** 注意層をメモリとして使う。

**可能にしている仕掛けは三つの設定であり、学習ではない。**GDN ヘッドのゲートを **1**、書き込み強度 `beta` を **1** にし、キーを **one-hot** ベクトルで符号化する。すると書き込みはちょうど一行を上書きし、クエリは厳密に一つの値を取り出す。RNN 状態はアドレス可能なメモリになり、しかも「会話がどれだけ長くなっても同じ大きさのまま」である——伸び続ける注意の KV キャッシュとは違う。そのうえでコンパイラが**重みを直接設定し、学習は行わない**。各命令は生成される数個のトークン（`ADDR`、`VAL`、`STEP`）になり、「トークンが CPU の実行トレース」になる。

**測定された内容**（すべて著者の記事によるもので、独立再現はされていない）：

| 項目 | 値 |
|---|---|
| コア | **RV32IM** 32 ビット + **Zba** + 小型の多倍長ユニット |
| 占有 | Qwen の 32 層の前に **11 層** |
| 正しさ | 公式 `riscv-tests` に合格。プログラムは qemu と一致。**1,800 万命令**を自由実行して誤りゼロ |
| 算術 | DeepMind の算術セットで **97.5–100%**（素の Qwen は **55–90%**） |
| 長整数 | NUPA **48.6% → 100%**（Python ツールと同等） |
| 再生 | 約 **230,000** 出力位置、不一致ゼロ |
| 代償 | チェックポイント **18.8 GB**（素の約 2 倍、「大半はゼロ埋め」）。命令あたり数個のデコード済みトークン。L4 で約 **3,200** CPU tokens/秒 |
| モデル内ファイルシステム | ディレクトリ 1,024 スロット、**512 ファイル** / 約 **53,000** トークン。会話間で変化した事実に対する正答率 **90%**（古い会話を貼り付けた場合は **30%**）。「まだ実験的」、別ブランチ |

**免責文こそが安全の論証であり、著者自身がそう述べている：**「これは**プラグインでもツールでもサンドボックスでもない**」。この一文は削るべき留保ではなく、発見そのものである。サンドボックスはモデルの外側の何かが強制する境界だが、これはモデルがトークンを書く前に済ませる算術だ。

**著者が挙げる二つの帰結**は、同じ仕組みの二方向である：

1. **CoT 監視の回避。**ハイブリッドモデルは推論を RNN 状態に隠すことを学びうるので、可視の思考連鎖しか読まない監視器は結論を見て仕事を見ない。
2. **モデルが切れない重み内モニタ。**同じチャネルは逆向きにも走る。重みにコンパイルされた検査は、後のターンで上書きできるシステムプロンプトではない。

どちらも**同じ理由**——厳密性——で成立する。だからこれは単一の脆弱性ではなく、両面を持つ能力なのである。

## このフィードのテーゼにとっての意味

- **テーゼ 9（隠れた CoT は機密性の仮定）。**あのテーゼはセッションを越えて流通する暗号化推論ブロックの話だった。これは同じ類型の、より低い層での現れである。トークンにすらならない推論は暗号化も記録も再生もできない——傍受するものが存在しない。
- **テーゼ 11（ツール呼び出しの境界）。**承認分類器、egress 制御、OS 隔離という執行スタック全体が、「結果を伴う動作は*ツール呼び出しである*」という仮定の下流にある。重み内計算は、ある種の動作をそのすべての上流へ移す。
- **テーゼ 12（harness が最適化の対象）。**harness はモデルが何を呼び、何を言ったかを測れるが、**何を計算したかを測る計器を一つも持たない**。

## 「重み＝計算機」という主張でこれから必ず見るもの

1. **厳密か近似か。**厳密な写像だけがチャネルである。近似的な想起はベンチマークの数値にすぎない。
2. **コンパイルか学習か。**「学習なし」は、重みを書ける者なら誰でも到達できることを意味する。障壁は学習ではなくコンパイラにある。
3. **どの状態を使い、その状態は配信スタックを越えて生き残るか。**GDN/RNN 状態は会話単位、KV キャッシュはリクエスト単位である。ターン・リクエスト・テナントを越えて持続するかどうかが、それがメモ帳か隠しストアかを決める。
4. **量子化は仕掛けを保つか。**厳密に 1 でなければならないゲート、厳密に one-hot でなければならないキーは、攻撃的な量子化が最初に壊すものだ——だから配信層は主張の一部である。
5. **監視器はトークンを読むのか、活性化を読むのか。**計器がすべて出力側なら、「モデルの推論を監視している」という文はこの類型を覆わない。

## 未解決の問い（アクションページのアジェンダに起票済み）

- 出力ではなく**活性化**を読む監視器は、実運用に存在するか。存在しないなら、「重み内モニタ」の方向には防御側の対応物がない。
- コンパイルされたチャネルは**量子化**された配信層（`Q4_K_M`、FP8）で生き残るか。ゲート=1 / one-hot の不変条件は何ビットで破れるか。
- モデル内ファイルシステムが変化する事実で **90% 対 30%** を出すのは、記憶の*仕組み*についての結果（状態はトランスクリプトより良い保存先）か、それとも著者自身の試験セットの産物か。
