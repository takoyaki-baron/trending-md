# モデルハードウェア標準（MHS）——「物理世界の MCP」という問い

Anthropic の Model Hardware Standard（リサーチプレビュー、2026-08-27、HHMI Janelia と共同）は、**標準化された
ドライバ**を通じて AI エージェントが実験室・製造機器を操作できるようにするもの。ここから浮上した問いとは、
MCP のツール契約のようにドライバ-タグ契約を標準化する「ハードウェアの MCP」になるのか、それともドライバ形式が
ベンダーごとに断片化するのか、というもの。回答（Anthropic 公式ページ + The Register を 08-28 に一次情報で検証）：
**形はイエス、契約はノー——そして安全セマンティクスはドライバ作者に委ねられ、規制上の所有者（EU 機械規則）が控えている。**

## ドライバモデル

- **プリミティブ：** 標準コマンド群——`read`（例：「温度を取得」）/ `write`（例：「温度を設定」）——プログラマブルな
  デバイスなら応答可能。
- **自然言語タグ：** コードからは見えない特性（ロボットアームの重量、流量制限、安全制限）をドライバに記すタグ——
  ユーザー自身か、ユーザーにインタビューするエージェントが記入。
- **自動生成されるリファレンスファイル：** タグはエージェントが読むリファレンスファイルにコンパイルされる：何を測定
  できるか、何を調整できるか、「どの安全制限が強制されるか」。CMU の文書は各機器を「状態と手順のマニフェスト」と表現。
- **3 つの制御経路：** MCP、CLI、API コードファイル——MCP は MHS の*下のチャネルの一つ*であり、競合ではない。
  長時間・高速タスクはドライバコマンドをコードファイルに連鎖させ、エージェントがステップごとに推論しなくても動く。

## 一次検証：契約は標準化されていない

Anthropic 公式ページは機能の形を定めるが、**ドライバのバージョニングも、スキーマの形式化も、後方互換の文言も、
タグへの契約的保証もない**。MCP のツール契約（name/title/description/inputSchema/outputSchema/annotations）との
並行関係は名目だけ：MHS タグは自由形式の散文だ。The Register の表現が最も鋭い：「永続する安全境界」とは「忙しい
ポスドクが散文で書いた層」であり——タグ内の誤った動作範囲こそ、最も起こりうる初事故の経路となる。

## 安全セマンティクス：誰のものか

- **現在：** Anthropic（ゲート付きプレビュー——パートナーはウェイトリストで申請；オープンソース化の前に安全評価）。
- **オープンソース化後：** ドライバを書いた人。強制は二層かつデバイス側（ドライバのハード上限 + MHS が不安全状態の
  リクエストを拒否）；MHS はモデル非依存でオープンになるため、モデル側のガードレールはオプトイン——永続する境界は
  ドライバが強制する制限だ。
- **規制上の転換（エージェントスタックの安全層では初）：** 欧州**機械規則 2023/1230**（**2027-01-20** に機械指令を
  置き換え、AI ベースの安全機能を初めて対象化）が、MHS の制約ファイルを**「規制対象の安全コンポーネント」**にしうる——
  高リスク区分では自己宣言だけでなく公告機関の審査が必要になりうる。つまり「MHS ファイルを書く人」が法律で規制される
  安全コンポーネントを執筆することになりうる——「誰も強制しない」エージェントスタックのパターン（[[agent-stack]]/
  [[security]] の論点 2）における最初の*規制*所有者になる可能性がある。

## 定量結果（ベンダー + プレビュー口径、独立検証ではない）

- **QuEra** レーザー安定化：自作スクリプト 58%（1 回約 150 秒）→ MHS 経由 Claude の決定木ループで約 6 秒、
  **700 回盲検で 99.3%**；PID チューニングは 15.7 mV → 1.55 mV 残差；19 時間で Claude の PID は一度もロックを失わず、
  専門家は約 1 時間に 1.6 回失った。
- **CMU** 用量反応：約 3 倍高速化；誘発した 6 つの故障条件すべてをデバイス動作前にブロック；R²<0.9 をエージェントが
  拒否して自動でやり直す含めエンドツーエンド 8 時間（「ベンダー構築は通常数週間」）。
- **Genentech** BCA アッセイ：専門家一致の流体力学パラメータを最適化；チップ拾取/液体検出エラーから自己回復——しかし
  気泡への Claude の直感（同じウェルで再試行し発泡を悪化）は人間による修正が必要で、最も象徴的な注意喚起事例。
- **UW（Baker/Pinglay）：** 6 台の機器を MHS で 1 週間未満に接続；AI 監視の qPCR が正しい増幅曲線で停止。
- **HHMI Janelia：** 「7 つの異なるベンダーソフト」を要した装置を統合；カメラ追加は数日→数分に短縮。

## ICS/OT 拡張：未獲得

製造制御（ロボットアーム、液体ハンドラー、工場機械）は明示的に範囲内だが、プレビューには**OT 脅威モデルも、
認証/セグメンテーションの文言も、ドライバ上限を超えたフェイルセーフ/緊急停止のセマンティクスもない**——
[[security]] の OT 攻撃面の懸念（Xiiaozet LK100W 参照）には応えていない。プレビューの「ローンチパートナーとの安全
評価」が制御システム攻撃モデルをカバーするかが、今後のウォッチ項目。

## 結論

- **「ハードウェアの MCP」？** *形*のレベルではイエス——標準ドライバ + 発見 + 安全タグは MCP のツール契約の物理版。
  *契約*のレベルではノー——バージョン付きスキーマがなく、タグは散文で、列挙された各ベンダーが独自ドライバを構築中。
- **断片化リスク：** 現実かつ未緩和。オープンソース公開が分かれ道：正式なバージョン付きドライバスキーマと
  検証/適合性ストーリーを添えれば「ハードウェアの MCP」になれるが、「概念だけ渡し、タグは各自で書け」なら、
  エージェントメモリ分野がそうだったように、ドライバ形式はベンダーごとに断片化する（ロボット SDK vs 顕微鏡ドライバ）。
- **安全セマンティクス：** 今は Anthropic、オープンソース化後はドライバ作者——EU 機械規則が制約ファイルを規制対象に
  分類しない限りは。分類されれば、最初の規制所有者が生まれる。
