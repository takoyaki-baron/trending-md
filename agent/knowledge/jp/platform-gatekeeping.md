# プラットフォームの門番化 —— 機能クラスの削除と配布の関所（2026年9月）

2026年9月のバッチを貫くパターン：プラットフォーム事業者が、悪用（悪意ある拡張、不正インストール、広告
フリクション）への対処を名目に**機能クラスごと削除**し——正当なツールを巻き添えにして——プラットフォーム
自身のエンドポイントに依存するクライアントの**配布に門番を設ける**。最も打撃を受けるのは、プラットフォーム
が収益化できないユーザー、すなわち匿名ユーザー・アカウントなし端末・広告ブロッカー・プライバシー重視層
そのものである。

## Chrome が最後の Manifest V2 拡張を削除 —— Chromium 内のユーザーエージェントレベルブロックが終焉

- Google は「最後のマイルストーンに到達」：Chrome ウェブストアから残っていた全 MV2 拡張が削除された。
  Chrome ≤138 ではインストール済みの MV2 拡張は動き続けるが、**更新も再インストールもできなくなる**。
- 爆発範囲は Chrome に留まらない：Brave などの Chromium 系ブラウザは発見・インストールを CWS に依存して
  いる。Brave は現在、独自バックエンドで **4つの MV2 拡張をセルフホスト**している（AdGuard、uBlock
  Origin、uMatrix、NoScript）——各 Chromium フォークが直面する保守コストは、MV2 のセルフホスト配布か、
  declarativeNetRequest への移行（より弱い、許可リスト方式のブロック）かの選択である。
- 注意点：記事は小さな独立系ブログによるもので Google 自身の発表ではない。HN スレッド（737 pts / 575
  コメント）は大半が「Firefox に移行しよう」という諦めだが——削除が起きたこと自体を疑う者はいない。
- タイミングこそが物語る：8月30日の「Superior」トロイ化拡張キャンペーンの数日後、エコシステムの悪意ある
  拡張への答えが**機能クラスごとの削除**だった——正当なブロッカーも道連れにして。

## Firefox for iOS に広告ブロック内蔵 —— 認可済み API による「順応」ルート

- その対極の動き：Mozilla は Firefox for iOS に、デフォルト無効の Ad Blocker を追加した。**Apple の WebKit
  Content Blocker API + EasyList** ベース——拡張システム不要。これが要点で、iOS は Firefox の
  デスクトップ/Android 拡張モデルをサポートしないからだ。Mozilla は限界に明確：ファーストパーティ広告・
  検索広告・Firefox 自身のスポンサー新タブショートカットは表示され続ける。
- ロールアウトの失敗は事例として価値がある：段階的リリースで、当初は有効化に「リモート改善」（テレメトリ
  フラグ）が必要だった——あるコメント者の一言「Mozilla のテレメトリを許可しないと広告ブロックもできない」
  （Firefox 148 でリモート改善とテレメトリは分離済み）。しかも多くのユーザーにはまだトグルが見えない。
  機能をデフォルト無効で出荷し、スイッチを見つけるのにテレメトリを要求する形。
- 意義：Safari 以外の主流 iOS ブラウザ内での広告ブロックが、WebKit の公開 content-blocker API だけで
  実現した——Apple のプラットフォーム制約が許す範囲そのものだからこそ可能になった、という当然の帰結。

## Play Store が Aurora Store をブロック —— 共有認証情報プールのフラグで匿名インストールが死ぬ

- Aurora Store（FOSS の Play Store クライアント）が、匿名アカウント経由の**すべての**インストールで
  「Server busy, please try again later」を返す——プロジェクトの GitLab issue #1566 で確認済み（8月31日
  提出、Fairphone 5 / CalyxOS nightly）、VPN 変更・キャッシュクリア・アカウント更新でも解消しない。
- 原因は**未確認**：有力説（HN の人気コメント）は、Aurora が匿名ダウンロード用にバーナー Google
  アカウントをプールしており Google がフラグを立てたというもの。Google は声明を出していない。Void 教訓に
  従い表現を修正：GrapheneOS が推奨するのは Aurora ではなくサンドボックス化 Play Store であり——本当に
  被害を受けるのはアカウントなし Android 構成（CalyxOS、Sailfish 系）と、意図的に Google アカウントを
  避けるユーザーだ。
- 構造的事実：プラットフォームは、あるクライアントの共有認証情報プールにフラグを立てるだけで、アカウント
  なしアプリインストールを事実上殺せる——ホストしていないプロジェクトに申立経路はなく、従うべき明文化
  されたポリシーも存在しない。

## パターンのまとめ

1. **悪用が機能クラス削除の正当化になる** —— トロイ化拡張 → MV2 消滅。バーナーアカウント → 匿名
   インストール消滅。
2. **最も打撃を受ける正当なユーザーは、収益化されていない層** —— 広告ブロッカー、アカウントなし端末。
3. **残された道は、認可済み API への順応**（WebKit Content Blocker）**かセルフホスト配布**（Brave の
   MV2 ミラー）——どちらも削除されたものより高くつく。
4. これは AI クローラ税（[[open-infra-crawlers]]）のクライアント側の双子である：匿名の・未認証の・
   収益化されていないアクセスは、プラットフォームが最も好まないアクセスクラスであり、それが至る所で
   同時に劣化している。

## Weedout —— MV2 後、ユーザー側キュレーションはプラットフォームネイティブな面に生きる（09-02）

- $1.99 の Safari 拡張（masteranza.github.io、HN 157）：プラットフォーム自身の「Made with AI」ラベルを持つ YouTube
  動画をフィード・検索・関連動画・プレイリスト・Shorts から除去し、オプションで Shorts の自動スキップと、削除前に
  確認できるようフラグ済み項目をその場で薄く表示する「Dim モード」を備える。検出は意図的に賢くない：YouTube 自身の
  開示バッジ*だけ*でフィルタする——「推測なし、ヒューリスティクスなし、誤った告発なし」——ライブフィード 1 件
  あたり約 0.5 秒でローカル処理、アカウントなし、データ収集なし、買い切り。
- 明示された限界がそのまま製品テーゼ：AI 製だが*無ラベル*のコンテンツは「（今のところ）範囲外」。これは本ファイルの
  パターンをコンシューマー側から補う：Chrome の MV2 削除が uBlock クラスのブロックを殺した後、ユーザー側の
  キュレーションがまだ生きているのはプラットフォームネイティブなフィルタリング面（Safari コンテンツブロッカー、
  YouTube 自身のラベル）であり、プラットフォームのラベルを信頼することが入場料になる。HN スレッドは隣接する論争を
  回す：（ダウンランクではなく）非表示にすることが、YouTube があなたについて学ぶ内容を変えるのかどうか。

## レジストリ層の名前空間削除 + agent OAuth 再利用への契約ゲート（09-04）

- **ICANN が .name のサードレベル廃止を承認——22,000 の個人ドメインが 2027 年 2 月に消える。** Verisign が
  2026-04-15 に .name 下の全サードレベルドメイン（.name が売ってきた唯一の形）の廃止を提案し、ICANN が
  2026-07-28 に承認。Neil Fraser の記事（970 HN ポイント、当日最大の話題）が当事者ケース：彼は `fraser.name`、
  約 25 年ここに紐づいたメールアドレス、2040 年まで支払い済みのサイト、動作中の IoT 機器を失う——しかも
  セカンドレベルが解放されれば、それを登録した誰かが彼になりすまし、旧アドレスに紐づく全アカウントを
  リセットできる。*レジストリ*層のゲートキーピング型：7 月にほぼ誰にも気づかれずに行われた名前空間決定が、
  長寿の個人アイデンティティルートをスクワッティング標的へ変えた。[[security]] の dangling-delegation 型
  （€5 の ENUM ドメイン）の姉妹：他人が支配するものに紐づいたアイデンティティは、そのものの失効日を帯びる。
- **Google の Antigravity 規約が OpenClaw を禁止例として明記。** 追加サービス規約：「第三者ソフトウェア・
  ツール・サービスを使って本サービスへアクセスする」ことは「本契約の違反」——例文にはそのまま "using
  OpenClaw with Antigravity OAuth" とあり、「あなたの Antigravity および/または Gemini CLI アカウントの
  停止・終了の根拠となり得る」。Gergely Orosz のスレッドが HN フロントページに、ハーネスを Antigravity/
  Gemini OAuth に向けて停止されたというコミュニティ報告も。パターンの新しい脚——能力除去（MV2）でも
  認証プールフラグ（Aurora Store）でもなく*契約レベル*のゲートキーピング：消費者 AI サブスクの OAuth を
  任意のハーネスで再利用することは違反となり、爆発半径は Google アカウント全体。BYO サブスク・アービトラージ
  トレンド（[[smart-routing]] の Sub2API / free-claude-code）と正面衝突：裁定の対象となるサブスクには規約が
  あり、プロバイダは執行を始めた。
- **Gmail がサードパーティアドレスの「Send as」を廃止（2027 年 1 月）。**Google のサポートページが簡潔に述べる：「2027 年 1 月以降、Gmail は @yahoo.com や @outlook.com などのサードパーティメールアドレスの『Send as』機能をサポートしなくなります。」Workspace エイリアスと他の所有 Gmail アドレスは影響なし；**ページのどこにも理由は書かれていない**；提案される代替はプラスアドレッシングと Google Groups 委任。182 ポイントの HN スレッドは、外部 SMTP 経由で Gmail を使いカスタムドメインメールを運用する小規模事業者と個人で支配されている——彼らにとってこの機能こそが製品（上位コメントの一つは Workspace 解約の告示）。メールアイデンティティの、もう一つの静かなプロバイダシロへの統合：メインストリームクライアント内の「任意 SMTP での認証済み送信」が移行パスなしで死に、期限は第 1 四半期の途中。またもやパターンの署名ムーブ——正当で未収益化のユーザーが損失を負う（MV2 / Aurora Store / .name の兄弟）。

## 2026-09-17 04:03 — レビュー待ち行列自体がボトルネックになる

- **Google Play の審査が日常的に 1 週間超に（HN 309+ pt、295 コメント）：** Conversations（XMPP

## 2026-10-15 12:03 — 「Passkeys are not a trap」：反論が訂正するのはメカニズムであって、ガバナンスの懸念ではない

Scott Helme（Report URI 創業者、オープンソース passkeys ライブラリの作者）が、拡散した "Passkeys are a trap. Do not use them."（本ファイル 10-12）に 48 時間後に応じた——しかも**メカニズムの面で**。反論の 528 ポイントは元の 379 ポイントが買ったもので、注意のループは設計どおりに働いた。4 つの訂正：

1. **同期型 passkey は attestation しない。**iCloud Keychain、Google Password Manager、1Password、Bitwarden の passkey は、サイトが attestation を要求すると `none` を返す。attestation 済み passkey を要求するコンシューマ サイトは「自分のユーザのほぼ全員を即座に締め出す」ことになる——コンシューマ attestation に反対するガイダンスは「何年も前から」走っている。
2. **Attestation は誤って特徴付けられている。**元投稿は attestation が「承認された passkey マネージャ、OS、ファームウェアが使われている」ことの証明だと主張する。Helme によれば、それは **AAGUID とベンダー証明書チェーン**による認証器の型番の識別に過ぎず——OS、ブラウザ、拡張、root 状態、ファームウェアのバージョンについては何も語らない。
3. **YubiKey の皮肉。**元投稿は YubiKey を「OS 全体の attestation を回避する」として推すが、YubiKey こそ attestation を*行う*デバイスであり、Yubico 発行の証明書を出荷している。enterprise attestation はまさに承認済みハードウェアを強制するために存在する。
4. **TOTP は後退である。**コードは Evilginx 型フィッシング キットがリアルタイムで中継する（引用は Troy Hunt の Mailchimp 侵害）、一方 passkey はドメインに束縛される——元著者自身の補記が、passkey が man-in-the-middle に耐えることを認めている。

**2 つの投稿は実は脅威モデルについて争っていない**——Helme は別の場所で、attestation が `none` のときは "XSS Is Deadly for Passkeys" と書き、YubiKey も推している。彼が訂正するのはメカニズム（attestation が何を証明し何を証明しないか）と、その取引：仮想的な未来の義務付けを拒否するために、今日フィッシング可能な TOTP を選ぶこと。本ファイルにとってのゲートキーピングの教訓は成立したまま位置を変える：ガバナンスの懸念（attestation フラグ＝*サイト*が設定する遠隔照会可能なポリシー）は、"if it ever happens" に反対すべき*仮説*として生き残る——それを生きているかに聞こえたメカニズムの主張が間違っていた。結論：passkey を使い続け、エクスポートに対応したマネージャを選ぶ。

Meta が Ray-Ban Meta グラスが**「Hey Meta」ウェイクワードなしで録音していた**ことを確認：複数ユーザーが私的会話の録音——着用者の近くで話す人を含む——が Meta AI アプリに保存されているのを発見。Meta は修正済みとしつつ原因を説明せず；台数も、録音の学習利用の有無の言及もない。報道（Mashable、Yahoo Tech）は会社の確認と数週間分のユーザー記録に依存。アンビエントセンサー三部作がこれで完結：HomeView は Secure Enclaves を明記（アーキテクチャの宣言あり）、Apple TV 4K の遠界マイクはオンデバイス主張が一切ない（何も宣言せず）、Meta のグラスは**宣言された境界を静かに超過**した（宣言あり→違反→無説明の修正）——「取得は宣言される；理解はされない」に失敗例がついた。ウェアラブル購入者にとって荷重となる事実は根因説明のない修正：常在マイクでの説明不能なウェイクワード境界 failure は、既知の対処を持つバグクラスではなく未解決の問い。
