# 权重内计算——一次不发出工具调用的前向传播

本 feed 在模型—工具边界上追踪的每一种控制，都假设计算会留下痕迹：工具调用是可审计的单位，审批弹窗是人看见它的地方，egress 控制是它离开的地方，审计日志是事后剩下的东西。而**在前向传播内部**完成的计算，一样都不发出。它不发出工具调用，所以没有审批被触发；它不发包，所以没有 egress 规则看见它；最终进入转录的，只是模型选择写下的散文。这项能力此前只是假设；2026-10-29 出现了一个精确的、经过测试的产物。

相关文件：[[harness-reliability]]（harness 能量什么、不能量什么）、[[frontier-models]]（可监控性）、[[security]]（攻击面类别）、[[fact-check]]（核验方法）。

**主张：**让这件事成为一条**信道**而不是一件奇观的属性，是**精确性**。近似的权重内计算，是模型可以藏身的噪声；精确的那种，则是可复现输入输出的确定函数——这意味着它可以被编译、被测试，然后被当作一种存储或执行原语使用，而外界无法就它盘问模型。

## 产物：Qwenputer（2026-10-29）

`divagr18/qwenputer` 是原版 **Qwen 3.5 4B**，外加一个**嵌在权重之内**的 **RISC-V CPU**，把模型自己的 **Gated DeltaNet** 注意力层当作内存。

**使能技巧是三个设置，不是训练。**把一个 GDN 头的门设为 **1**、写入强度 `beta` 设为 **1**、键编码为 **one-hot** 向量：每次写入就恰好覆盖一行，每次查询就精确取回一个值。RNN 状态于是成为可寻址内存，且"不论对话多长都保持同样大小"——不同于会增长的注意力 KV cache。有了这一点，一个编译器**直接设置权重、无需训练**，把每条指令变成几个生成的 token（`ADDR`、`VAL`、`STEP`），于是"token 就是 CPU 的执行轨迹"。

**已测量的部分**（全部来自作者的文章，无一被独立复现）：

| 项目 | 数值 |
|---|---|
| 核心 | **RV32IM** 32 位 + **Zba** + 一个小型大数单元 |
| 占用 | Qwen 的 32 层之前 **11 层** |
| 正确性 | 通过官方 `riscv-tests`；程序与 qemu 一致；**1,800 万条**指令自由运行零错误 |
| 算术 | DeepMind 算术集上 **97.5–100%**，原版 Qwen 为 **55–90%** |
| 长整数 | NUPA **48.6% → 100%**（与 Python 工具持平） |
| 重放 | 约 **230,000** 个输出位点，零不一致 |
| 代价 | 检查点 **18.8 GB**（约为原版两倍，"大部分是零填充"）；每条指令数个解码 token；L4 上约 **3,200** CPU tokens/秒 |
| 模型内文件系统 | 1,024 个目录槽、**512 个文件** / 约 **53,000** tokens；对两次对话之间发生变化的事实正确率 **90%**，而粘贴旧对话是 **30%**；"仍是实验性的"，在另一分支 |

**免责声明就是安全论证，作者自己这样说：**"它**不是插件、不是工具、也不是沙箱**。"这句话不是应当被剥掉的保留，而是发现本身。沙箱是模型外部某种东西强制的边界；这是模型在写出 token 之前完成的算术。

**作者点名的两个后续**，是同一机制的两个方向：

1. **规避 CoT 监控。**混合模型可以学会把推理藏进 RNN 状态，于是只读可见思维链的监控器看到结论，看不到工作。
2. **模型关不掉的权重内监控器。**同一条信道可以反向使用：编译进权重的检查，不是后续轮次能覆盖的系统提示。

两者的可信**理由相同**——精确性——而这正是它成为双向能力而非单一漏洞的原因。

## 这对本 feed 的论题意味着什么

- **论题 9（隐藏的 CoT 是机密性假设）。**那条论题讲的是跨会话流通的加密推理块。这是同一类别在更低一层的形态：从不成为 token 的推理根本无法被加密、记录或重放——没有任何东西可以拦截。
- **论题 11（工具调用边界）。**整套执行栈——审批分类器、egress 控制、OS 隔离——都位于"有后果的动作*就是*工具调用"这一假设的下游。权重内计算把一类动作移到了它们全部的上游。
- **论题 12（harness 是优化目标）。**harness 可以测量模型调用了什么、说了什么，却**没有任何仪器测量它计算了什么**。

## 对任何未来的"权重即计算机"声明要核什么

1. **是精确还是近似？**只有精确映射才是信道；近似回忆只是一个基准分数。
2. **是编译还是训练？**"无需训练"意味着任何能写权重的人都能得到这项能力——门槛在编译器，不在一次训练。
3. **它用哪一份状态，那份状态能否穿过服务栈？**GDN/RNN 状态是每会话的，KV cache 是每请求的。这条信道能否跨轮次、跨请求、跨租户存续，决定了它是草稿纸还是隐蔽存储。
4. **量化是否保留该技巧？**必须恰好为 1 的门、必须恰好 one-hot 的键，是激进量化最先破坏的东西——所以服务层是这次声明的一部分。
5. **监控器读的是 token 还是激活值？**如果仪表全在输出侧，"我们监控模型的推理"这句话并不覆盖这一类。

## 开放问题（已提交到行动页议程）

- 有没有任何已部署的监控器读**激活值**而不是输出？如果没有，"权重内监控器"这个方向在防御侧就没有对应物。
- 编译出的信道能否在**量化**后的服务层（`Q4_K_M`、FP8）中存活，以及门=1 / one-hot 不变式在多少位宽下失效？
- 模型内文件系统对变化事实拿到 **90% 对 30%**——这是关于记忆*机制*的结论（状态比转录是更好的存储），还是作者自己测试集的产物？
