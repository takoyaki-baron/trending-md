## 2. Metabase ゼロデイSQLインジェクション（CVSS 10.0） — 悪用が確認され、複数組織が侵害される

- **Velocity:** ▮▮▮ trending
- **Source:** The Hacker News · 850+ pts · 8h ago
- **Tags:** `security` `sql-injection` `zero-day` `metabase` `cve`

Metabaseの`POST /api/session/reset_password`エンドポイントに存在する深刻な未認証SQLインジェクション（GHSA-vwf4-m7j8-wcjf、CVE-2026-72898）がCVSS 10.0と評価され、公開前に野生下で悪用された。巧妙に細工された単一のリクエストがHoneySQLの一括パラメータ汚染を介して生SQLを注入し、PostgreSQLバックエンドで管理者セッションを作成。0.58.0からプレパッチ0.63.xまでのすべてのセルフホストバージョンが影響を受ける。被害確認済み：Framework（顧客PII）、Tally（メールとパスワードハッシュ）、Privy、LexisNexis。

**Why it matters:** CVSS 10.0、ユーザー操作不要。Metabaseは本番データベースの認証情報を保持しているため、1つのインスタンス侵害が接続されたすべてのデータソースに連鎖する。侵害指標：`POST /api/session/reset_password` → HTTP 400 → `GET /api/user/current` → HTTP 200 = 侵害確定。

> 緊急パッチ：0.58.24 / 0.59.21 / 0.60.17 / 0.61.11 / 0.62.9 / 0.63.5。パッチ後：全セッション失効、DB認証情報ローテーション、APIキー監査が必須。

## 7. Django 6.1リリース — フィールドフェッチモードがN+1クエリ問題を解決

- **Velocity:** ▮▮ rising
- **Source:** Django Project · 460+ pts · 18h ago
- **Tags:** `django` `python` `web-framework` `release` `orm`

Django 6.1がリリースされ、`QuerySet.fetch_mode()`が主要機能として登場：`FETCH_PEERS`はN+1クエリをオンデマンドで2回に圧縮し、`RAISE`はパフォーマンスクリティカルなコードでの意図しない遅延クエリをブロック。その他：データベースレベルの`ForeignKey.on_delete`（DB_CASCADE/SET_NULL/SET_DEFAULTがSQLで直接実行されオブジェクトをメモリにロードしない）、辞書ベースの`MAILERS`設定（マルチバックエンドメール）、`UUID4`/`UUID7`関数、明示的なJSON null処理のための`JSONNull`。Python 3.12～3.14対応。

**Why it matters:** Djangoは依然としてPythonで最もデプロイされているWebフレームワーク。N+1クエリは最大のパフォーマンス落とし穴 — `FETCH_PEERS`が`prefetch_related`のボイラープレートなしにORMレベルで解決。`DB_CASCADE`オプションは劇的に高速だがシグナルをスキップ — すべてのチームが理解すべきトレードオフ。

> 破壊的変更：`first()`/`last()`が暗黙的なPKソートを行わなくなった。PostgreSQL 14サポート終了。最低SQLite 3.37.0。

[`🔗 Django Project`](https://www.djangoproject.com/weblog/2026/aug/05/django-61-released/) · [`🔗 Django News`](https://django-news.com/archive/issue-349-django-61-and-a-dsf-executive-director/) · [`🔗 Django 6.1 Release Notes`](https://docs.djangoproject.com/en/6.1/releases/6.1/)

## 9. SnowflakeがCDCをPostgres内部にプッシュ — 複製を時計仕掛けに、Apache Icebergに書き込み

- **Velocity:** ▮ steady
- **Source:** Snowflake Engineering Blog · 290+ pts · 22h ago
- **Tags:** `snowflake` `postgres` `cdc` `iceberg` `data-engineering`

SnowflakeはData Mirroring機能がPostgres内部からCDCをプッシュする仕組みを詳細に公開：新しい`snowflake_cdc`拡張が変更バッチをApache Icebergテーブル（S3上のParquet）に直接書き込み、外部CDCコネクタを不要に。4段階パイプライン（書き込み → デコード → キャプチャ → 適用）がトランザクション境界の整合性を保証。$liveビューで約30秒のデータ鮮度を実現。Ericssonは複製遅延を40日から1時間未満に短縮。

**Why it matters:** プルベースCDC（Debezium、Fivetran）は脆弱 — 外部ツールはネットワーク障害とデータベース障害を区別できない。Postgres内部からのプッシュベースCDCはアーキテクチャ的に明確。Icebergネイティブアプローチによりデータが即座にオープンフォーマットで利用可能に。

> 現在はSnowflake Postgres（マネージド）のみ。双方向ミラーリングは2026年後半に予定。`snowflake_cdc`はクローズドソース。
