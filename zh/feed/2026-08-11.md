## 2. Metabase 零日 SQL 注入漏洞（CVSS 10.0）—— 已被在野利用，多家企业遭入侵

- **Velocity:** ▮▮▮ trending
- **Source:** The Hacker News · 850+ pts · 8h ago
- **Tags:** `security` `sql-injection` `zero-day` `metabase` `cve`

Metabase `POST /api/session/reset_password` 端点存在严重的未认证 SQL 注入漏洞（GHSA-vwf4-m7j8-wcjf，CVE-2026-72898），CVSS 评分 10.0，披露前已遭在野利用。单个精心构造的请求通过 HoneySQL 批量参数污染注入原始 SQL，在 PostgreSQL 后端创建管理员会话。影响 0.58.0 至 0.63.x 补丁前所有自托管版本。已确认受害者：Framework（客户 PII）、Tally（邮箱和密码哈希）、Privy 和 LexisNexis。

**Why it matters:** CVSS 10.0，零用户交互。由于 Metabase 持有生产数据库的凭据，一个实例被攻破会连锁波及所有连接的数据源。入侵指标：`POST /api/session/reset_password` → HTTP 400 → `GET /api/user/current` → HTTP 200 = 已失陷。

> 紧急补丁：0.58.24 / 0.59.21 / 0.60.17 / 0.61.11 / 0.62.9 / 0.63.5。补丁后需：撤销所有会话、轮换数据库凭据、审计 API 密钥。

[`🔗 The Hacker News`](https://thehackernews.com/2026/08/metabase-zero-day-exploited-in-wild.html) · [`🔗 IONIX Threat Center`](https://www.ionix.io/threat-center/cve-2026-72898/) · [`🔗 SOCRadar`](https://socradar.io/blog/critical-metabase-zero-day/)

## 7. Django 6.1 发布 —— 字段获取模式终结 N+1 查询问题

- **Velocity:** ▮▮ rising
- **Source:** Django Project · 460+ pts · 18h ago
- **Tags:** `django` `python` `web-framework` `release` `orm`

Django 6.1 正式发布，`QuerySet.fetch_mode()` 成为标志性功能：`FETCH_PEERS` 按需将 N+1 查询压缩为 2 次，`RAISE` 在性能关键代码中阻止意外的惰性查询。其他亮点：数据库级 `ForeignKey.on_delete`（DB_CASCADE/SET_NULL/SET_DEFAULT 直接在 SQL 中执行，无需加载对象到内存），字典式 `MAILERS` 设置（多后端邮件），`UUID4`/`UUID7` 函数，以及 `JSONNull` 用于显式 JSON null 处理。支持 Python 3.12–3.14。

**Why it matters:** Django 仍是 Python 部署最广的 Web 框架。N+1 查询是头号性能陷阱——`FETCH_PEERS` 在 ORM 层面解决此问题，无需 `prefetch_related` 样板代码。`DB_CASCADE` 选项速度极快但跳过信号——每个团队都需要理解这个权衡。

> 破坏性变更：`first()`/`last()` 不再隐式按主键排序。PostgreSQL 14 停止支持；最低 SQLite 3.37.0。

[`🔗 Django Project`](https://www.djangoproject.com/weblog/2026/aug/05/django-61-released/) · [`🔗 Django News`](https://django-news.com/archive/issue-349-django-61-and-a-dsf-executive-director/) · [`🔗 Django 6.1 Release Notes`](https://docs.djangoproject.com/en/6.1/releases/6.1/)

Cactus Compute 发布了 Needle 2：一个 45M 参数模型，经 2-bit 量化压缩至 14MB，专为廉价设备上的工具调用设计。在树莓派 5 上达到 500 tok/s，在 200 美元以下的安卓手机上达到 300–700 tok/s。使用 Walsh-Hadamard 变换替代标准前馈层。不是聊天机器人——将自然语言映射为结构化函数调用，具备字节级语法保证。已搭载于 Pebble Index 01 智能戒指（75 美元）。

> 256 token 上下文，仅支持单轮。最佳搭配 ≤5 个工具。开源（MIT）。

## 9. Snowflake 将 CDC 推入 Postgres 内部 —— 复制如钟表般精准，写入 Apache Iceberg

- **Velocity:** ▮ steady
- **Source:** Snowflake Engineering Blog · 290+ pts · 22h ago
- **Tags:** `snowflake` `postgres` `cdc` `iceberg` `data-engineering`

Snowflake 详解了其 Data Mirroring 功能如何从 Postgres 内部推送 CDC：新的 `snowflake_cdc` 扩展直接将变更批次写入 Apache Iceberg 表（Parquet 格式存于 S3），消除了对外部 CDC 连接器的需求。四阶段流水线（写入 → 解码 → 捕获 → 应用）具备事务边界对齐能力。$live 视图提供约 30 秒的数据新鲜度。爱立信将复制延迟从 40 天降至不到 1 小时。

**Why it matters:** 基于拉取的 CDC（Debezium、Fivetran）很脆弱——外部工具无法区分网络故障和数据库故障。从 Postgres 内部推送 CDC 在架构上更清晰。Iceberg 原生方案意味着数据立即可用开放格式。

> 目前仅支持 Snowflake Postgres（托管版）。双向镜像预计 2026 年晚些时候推出。`snowflake_cdc` 为闭源。

## 10. Remix 3 Beta 抛弃 React —— Web 标准全栈框架，社区意见分裂

- **Velocity:** ▮ steady
- **Source:** InfoQ · 250+ pts · 24h ago
- **Tags:** `remix` `react` `web-standards` `framework` `preact`

Remix 3 beta（v3.0.0-beta.5）是一次彻底重写，完全抛弃 React，转向 Fetch API 路由、基于 Preact 分支的命令式模型（无虚拟 DOM，无 hooks），以及服务端驱动的"Frames"（类似 HTMX 的 HTML 片段）。一个 `remix` 包覆盖路由、中间件、认证、表单、数据和主题。现有 Remix 2 应用应迁移至 React Router v7——Remix 3 是全新起点，而非升级。

**Why it matters:** 这是自 Rails 引入 Webpack 以来最剧烈的框架转向。支持者称其为"Grug Brain 版本的 Next.js"；批评者认为其面目全非。"一个名字、三个产品"的现状（Remix 2 → Router 7，Router 7 独立版，Remix 3 beta）造成严重的迁移困惑。

> Shopify Hydrogen 继续使用 React Router v7。试用：`npx remix@next new my-app`。
